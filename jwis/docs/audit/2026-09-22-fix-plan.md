## Slice 1 — Correctness: stale bundles, auth, error boundary (P0, ~1 day)

### 1.1 `[FE]` Service worker must not pin old builds

**Problem.** `public/sw.js` is cache-first for every non-`/api` GET and
never revalidates. `index.html` (and thus the hashed chunk names) is served
from cache forever; users keep the previous release until they clear site
data. `CACHE_NAME = "jwis-demo-v1"` is never bumped.

**Change.**
1. `public/sw.js`: navigations (`request.mode === "navigate"`) and
   `/index.html` → network-first, fall back to cache only on fetch failure.
   Hashed `/assets/*` → cache-first is fine (immutable by name).
   `/api/*` → keep network-first, but only cache GETs that returned 200.
2. Build-stamp the cache: `vite.config.js` `define: { __BUILD_ID__:
   JSON.stringify(Date.now()) }`, and inject it into the SW at build time
   (simplest: rename `sw.js` → `sw.template.js`, write `dist/sw.js` in a
   tiny `closeBundle` plugin replacing `__BUILD_ID__`). `activate` already
   deletes other cache names, so a new build id evicts the old cache.
3. `src/main.jsx:63-67`: after `register()`, listen for `updatefound` →
   `statechange === "installed"` with an existing controller, and show a
   plain-language banner *"Versi baru tersedia — Muat ulang"* that calls
   `registration.waiting.postMessage("SKIP_WAITING")` then `location.reload()`.
   Add the matching `message` handler in the SW.

**Check.** Build, load app, edit any string, rebuild, reload once → new
string visible (or banner appears and one click shows it). No manual
`caches.delete`.

### 1.2 `[BE]` Protect every mutating endpoint

**Problem.** Only `POST /api/operations/{id}/approve` uses
`require_permission`. During the audit an unauthenticated
`POST /api/whatsapp/contacts {"drivers":{}}` wiped `driver_contacts.json`.

**Change.** In `backend/app/main.py`, add `Depends(require_permission(...))`
to:

| Endpoint | Permission |
|---|---|
| `POST /api/dispatch` | `dispatch:create` |
| `POST /api/dispatch/{id}/confirm` | `dispatch:confirm` |
| `POST /api/alert/follow-up` | `dispatch:create` |
| `POST /api/whatsapp/alert`, `/alert/simulate`, `/logout` | `dispatch:create` |
| `POST /api/whatsapp/contacts` | `admin:manage` |
| `POST /api/operations/plan` | `operations:plan` |
| `POST /api/events/permits` | `operations:plan` |
| `POST /api/fleet/astar-simulate-jam` | `operations:plan` |
| `POST /api/spj`, `/spj/{id}/stops`, `/activate`, `/complete`, `/cancel`, `/stops/{i}/complete`, `/receipt` | `dispatch:create` for create/activate/cancel; `dispatch:confirm` for stop-complete/receipt/complete |
| `POST /api/pretrip`, `/api/damage-reports` | `dispatch:confirm` |
| `POST /api/damage-reports/{id}/resolve`, `/api/service-records` | `dispatch:create` |
| `POST /api/ocr/timbangan` | `dispatch:confirm` |
| `POST /api/assistant/query` | `dashboard:read` |

`auth.py`: give `driver` `dispatch:confirm` only (already), and add
`dashboard:read` to `driver` **only if** the field app needs
`/api/dispatch/{truck}` — better: leave that GET open but scope it (see 1.3).

Token registry is in-process (`auth._TOKEN_REGISTRY`); acceptable for pilot
but add a 12 h expiry (`{tok: (role, issued_at)}`) so a leaked token dies.

**Change `[FE]`.** One `apiFetch(path, init)` helper in a new
`src/api.js` that injects `Authorization: Bearer ${localStorage.jwis_token}`
and, on 401, clears `jwis_*` keys and returns to login. Replace every
`fetch(\`${API_URL}...\`)` in `main.jsx`, `LiveFleetMap.jsx`,
`field/FieldApp.jsx`, `driver/DriverApp.jsx`, `field/OfflineOutbox.js` with
it (`grep -c 'fetch(\`${API_URL}' src/main.jsx` today: >60).

**Check.** `curl -X POST :8001/api/dispatch -d '{"truck_code":"T-001","instruction":"x"}'`
→ `401`. Same with a `driver` token → `403`. With `dispatcher` token → `200`.
Run `backend/tests` — several tests will need a login fixture; add one
`conftest.py` `auth_headers(role)` and use it, do not weaken the endpoints.

### 1.3 `[FE]`+`[BE]` Field app login and truck binding

**Problem.** `/field` has no login, a `<select>` lets any phone confirm any
truck's orders.

**Change.**
- `[BE]` `POST /api/auth/login` for `driver` returns `truck_code` (from a
  `JWIS_DRIVER_TRUCKS` env map or `driver_contacts.json`); token registry
  stores `(role, truck_code)`. `GET /api/dispatch/{truck}` and
  `POST /api/dispatch/{id}/confirm` reject when the token's truck differs.
- `[FE]` `field/FieldApp.jsx`: login screen (name + 4-digit PIN, 20 px,
  one button), then a fixed header "Agus Pratama · T-047", no truck
  selector. Remove the truck `<select>`.
- Reuse the `/driver` PWA visual pattern (`DriverApp.jsx`) — it is already
  Indonesian and large-target.

**Check.** Open `/field` fresh → login shown. Login as driver bound to
T-047 → `curl` with that token to `/api/dispatch/T-001` → `403`.

### 1.4 `[FE]` Error boundary

**Problem.** Any thrown render/effect error empties `#root` (see Slice 0
item 2). No recovery, no message.

**Change.** `src/ui/ErrorBoundary.jsx` (class component, `componentDidCatch`
→ `console.error`). Wrap each workspace in `main.jsx` `App` (per-workspace,
so the map dying leaves the nav usable) and wrap the whole `<App/>` once.
Fallback UI: *"Tampilan ini mengalami gangguan. [Muat ulang]"*, 18 px, one
button.

**Check.** Temporarily `throw` inside `WasteForecast` → nav still works,
fallback card visible; remove the throw.

### 1.5 `[BE]` Stop printing secrets at import

`backend/app/main.py:16-20`: delete the four `print(... API_KEY ...)` lines.
Replace with `logger.info("openai configured: %s", bool(key))`.

**Check.** `grep -n "API_KEY VALUE" app/main.py` → no match.

## Slice 2 — One source of truth for numbers (P0, ~1 day)

### 2.1 `[BE]` Executive summary must derive from the live snapshot

**Problem.** `main.py:648-651` defaults `top_spike=41`, `extra_trucks=28`,
`extra_crews=14`, `top_district="Jakarta Barat"`. `_top_prediction` often
returns a dict without those keys, so the defaults ship. KPI card says +4 %.

**Change.**
- Compute `top` from `snapshot["predictions"]` (max `spike_percent`), and
  `extra_trucks/crews` from the *same* `predictions_kecamatan()` call already
  made on line 664 (`top_hotspots[0].trucks_required` etc.). Remove all four
  literal defaults; if a value is unavailable, write *"tidak tersedia"* —
  never a plausible number.
- Same rule for `build_executive_summary()` in `data.py` (English variant).

**Check.** `jq '.summary' /api/reports/executive-summary` contains the same
percentage as `jq '.kpis.predicted_spike_percent' /api/command-center`.
Add `tests/test_executive_summary_consistency.py` asserting equality.

### 2.2 `[BE]` One TPA queue model

**Problem.** `route_decision()` (`main.py:1265`) runs
`simulate_queue(47 if jam_active else 14, …)` → 117 min; the TPA panel
uses `tpa_queue_status_payload()` → 15 min; `/api/ai/tpa-queue-live` is a
third model (`TpaQueuePredictor`).

**Change.** Make `tpa_queue_status_payload()` the single provider (it is
already cached per scenario); `route_decision` reads
`tpa_queue_status_payload(scenario="peak" if jam_active else "live")`.
Have `TpaQueuePredictor.update` publish into the same cache instead of its
own `latest()`; `/api/ai/tpa-queue-live` returns the same dict plus its
`trend`/`ci95` fields.

**Check.** With jam on and off, `route-decision.tpa_queue.wait_minutes ==
tpa/queue-status.avg_wait_minutes`. Test in `tests/test_queue_simulation.py`.

### 2.3 `[BE]`+`[FE]` Map-truth vs A* panel race

**Problem.** After `POST /fleet/astar-simulate-jam`, `/fleet/astar-reroute`
is fresh but `/fleet/map-truth` is served from a 4 s cache with
`abandoned_route: null`. E2E `map-workflow › jam toggle` reads
`.geometry` of `null`; users see panel "Dialihkan" while the map shows no
diversion.

**Change.** `post_astar_simulate_jam()` already exists at `main.py:1334`;
add `_map_truth_cache["ts"] = 0.0` (the same reset `_refresh_fleet_caches`
does for SPJ). `[E2E]` in the test, poll `map-truth` until
`t.abandoned_route` is non-null before dereferencing.

**Check.** E2E `jam toggle diverts T-047` passes 3× in a row.

Four workspaces render hardcoded arrays:

**Change.** Wire the first three to their endpoints (compliance is a

workspace or add a `StatusPill tone="warning"` *"Contoh tampilan — data
statis"* at the top and `data-simulated="true"` on the section. Never render
a green "Aktif/Online" badge from a constant.

**Check.** `grep -n '88.75\|RAD-MONAS-01\|16:45:12' src/main.jsx` → only in
the IoT block, and that block carries the label.

### 2.5 `[BE]` Assistant fallback

**Problem.** Without `OPENAI_API_KEY`, `POST /api/assistant/query` returns a
raw 500 `AI gateway error`; `.env.example` promises a local responder.

**Change.** `app/assistant.py`: when no key, answer from `rag.py` retrieval

*"Mode lokal — tanpa LLM"* pill. Remove the four `print("SYNC STEP …")`
lines in `assistant_query`.

**Check.** Unset the key, ask *"Berapa truk yang menyimpang?"* → 200 with a
sentence containing `2` (from `/api/fleet`), `mode: "local"`.

## Slice 3 — Operator UX for older / non-technical users (P1, 2–3 days)

Measured baseline (desktop 1440×900, after login): 58 text nodes ≤ 11 px,
43/112 targets < 32 px, 3 294 px tall, 9 nav items + 8 tabs, muted text
contrast 4.35 : 1. Targets: 0 text < 14 px, body 16 px, 0 targets < 44 px,
contrast ≥ 7 : 1 for body text, ≤ 5 nav items, one decision above the fold.

### 3.1 `[FE]` Type and colour tokens

`src/styles/tokens.css`:
```
--ui-ink: #121212;          /* keep */
--ui-muted: #4a4845;        /* was #7b7974 → 9.4:1 on white */
--fs-body: 16px; --fs-caption: 14px; --fs-label: 14px; --fs-kpi: 32px;
--tap-min: 44px;
```
Then replace every literal `font-size: 9|10|10.5|11|11.5|12|12.5|13px` in
`styles/*.css` (≈70 rules; list via `grep -n 'font-size: 1[0-3]' src/styles`)
with the tokens. Uppercase-tracking captions (`text-transform: uppercase;
letter-spacing`) → sentence case at 14 px; older readers parse sentence case
faster.

`main.jsx` has 197 inline `style={{…}}` props, many with `fontSize: "11px"`
— move them to classes while touching them; do not leave a second sizing
system.

**Check.** The audit's census script (in the audit doc, "font size census")
reports no key below `14px` on Armada, Prediksi, Perencanaan.
